# CloudSite 部署、升级与备份

## 干净安装

在一台只有 Docker Engine 与 Docker Compose Plugin 的服务器执行：

```bash
git clone https://github.com/nathanxiangang-web/CloudSite.git
cd CloudSite
cp .env.example .env
```

替换 `.env` 中的 `CLOUDSITE_SECRET_KEY`，确认镜像标签，再执行：

```bash
docker compose config --quiet
docker compose up -d
docker compose ps
curl -f http://127.0.0.1:3000/
```

验收重点：首次进入后台、保存 AList、首次同步、再次同步、搜索、预览、下载、分享和合集。

## 升级

升级会替换 API 与 Web 容器，不删除宿主机 `data/`。仍应先记录旧镜像标签并备份：

```bash
old_tag="$(sed -n 's/^CLOUDSITE_IMAGE_TAG=//p' .env | tail -n 1)"
bash scripts/backup.sh
docker compose pull
docker compose up -d
docker compose ps
curl -f http://127.0.0.1:3000/
curl -f http://127.0.0.1:3000/api/health
```

进入后台核对 API 版本、AList 连接、资源与目录数量、最近同步记录。不要只以容器 `Up` 作为通过依据。

## 回滚

如果只是新镜像启动失败，把 `.env` 中 `CLOUDSITE_IMAGE_TAG` 改回升级前的固定标签，然后执行：

```bash
docker compose pull
docker compose up -d
```

如果新版本已经修改数据库且需要回滚数据：

```bash
docker compose down
bash scripts/restore.sh cloudsite-backup-YYYYMMDD-HHMMSS.tar.gz --force
docker compose up -d
```

恢复脚本会在项目目录保留 `.restore-rollback-时间戳/`，可以再次撤销本次恢复。

## 备份

```bash
bash scripts/backup.sh
bash scripts/verify-backup.sh cloudsite-backup-YYYYMMDD-HHMMSS.tar.gz
```

API 运行时，备份脚本使用 SQLite online backup 获取一致的 `state.db` 与 `index.db`；其他数据文件和 `.env` 一并归档。API 未运行时直接复制静态数据库文件。

至少把备份复制到不同磁盘或不同主机。备份含 AList 加密凭据与密钥，权限应按敏感文件处理。

## 非破坏性恢复演练

不要直接覆盖生产目录。先恢复到临时目录并检查：

```bash
target="$(mktemp -d)"
bash scripts/restore.sh cloudsite-backup-YYYYMMDD-HHMMSS.tar.gz --target "$target"
find "$target" -maxdepth 2 -type f -print
```

确认 `.env`、`data/state.db`、`data/index.db` 存在，再删除临时演练目录。

## Traefik 部署

先核对 `.env` 中的域名、外部网络、入口点和证书解析器：

```bash
docker network inspect "$TRAEFIK_NETWORK"
docker compose -f docker-compose.traefik.yml config --quiet
docker compose -f docker-compose.traefik.yml up -d
```

Traefik 版不公开 `3000`/`8000`，回滚与备份命令需把 `docker compose` 替换为 `docker compose -f docker-compose.traefik.yml`。
