# CloudSite 离线安装

本文适用于目标服务器无法访问 GitHub Container Registry（GHCR），但已经安装 Docker Engine 与 Docker Compose Plugin 的场景。

当前 Release 同时提供 `linux/amd64` 与 `linux/arm64` 离线镜像。先执行 `uname -m`：`x86_64` 选择 `amd64`，`aarch64` 或 `arm64` 选择 `arm64`。

## 1. 下载附件

在能够访问 GitHub 的电脑打开 CloudSite Releases，下载同一版本的全部附件：

- `cloudsite-api-v0.3.2-linux-amd64.tar.gz`
- `cloudsite-api-v0.3.2-linux-arm64.tar.gz`
- `cloudsite-web-v0.3.2-linux-amd64.tar.gz`
- `cloudsite-web-v0.3.2-linux-arm64.tar.gz`
- `cloudsite-v0.3.2-offline-deploy.zip`
- `SHA256SUMS.txt`

不要混用不同版本的 API、Web 和部署包。

## 2. 校验文件

Linux：

```bash
sha256sum -c SHA256SUMS.txt
```

Windows PowerShell 可逐项执行：

```powershell
Get-FileHash .\cloudsite-api-v0.3.2-linux-arm64.tar.gz -Algorithm SHA256
Get-FileHash .\cloudsite-web-v0.3.2-linux-arm64.tar.gz -Algorithm SHA256
Get-FileHash .\cloudsite-v0.3.2-offline-deploy.zip -Algorithm SHA256
```

计算结果必须与 `SHA256SUMS.txt` 一致。校验失败时重新下载或重新传输，不要继续导入。

## 3. 复制到离线服务器

可使用移动硬盘、内网文件服务器或 `scp` 把四个附件放到同一目录。附件不包含 `.env`、数据库、AList 凭据或用户数据。

## 4. 导入镜像

```bash
arch=arm64 # x86_64 服务器改为 amd64
gzip -dc "cloudsite-api-v0.3.2-linux-${arch}.tar.gz" | docker load
gzip -dc "cloudsite-web-v0.3.2-linux-${arch}.tar.gz" | docker load

docker image inspect ghcr.io/nathanxiangang-web/cloudsite-api:v0.3.2 \
  --format '{{.Os}}/{{.Architecture}} {{.Id}}'
docker image inspect ghcr.io/nathanxiangang-web/cloudsite-web:v0.3.2 \
  --format '{{.Os}}/{{.Architecture}} {{.Id}}'
```

两个检查都应显示当前选择的 `linux/amd64` 或 `linux/arm64`。

## 5. 解压和配置

```bash
unzip cloudsite-v0.3.2-offline-deploy.zip -d CloudSite
cd CloudSite
cp .env.example .env
```

编辑 `.env`：

1. 把 `CLOUDSITE_SECRET_KEY` 替换为足够长的随机值。
2. 保持 `CLOUDSITE_IMAGE_TAG=v0.3.2`。
3. 按需要修改 Web 监听地址、端口和数据目录。

如果服务器没有 Python，可用 OpenSSL 生成随机密钥：

```bash
openssl rand -base64 48
```

密钥一旦用于保存 AList 凭据，不可随意更换。

## 6. 离线启动

必须同时指定基础 Compose 和离线覆盖文件。覆盖文件把 `pull_policy` 设置为 `never`，确保启动时不会连接 GHCR：

```bash
docker compose -f docker-compose.yml -f docker-compose.offline.yml config --images
docker compose -f docker-compose.yml -f docker-compose.offline.yml up -d --wait
docker compose -f docker-compose.yml -f docker-compose.offline.yml ps
```

`config --images` 应只显示：

```text
ghcr.io/nathanxiangang-web/cloudsite-api:v0.3.2
ghcr.io/nathanxiangang-web/cloudsite-web:v0.3.2
```

访问 `http://服务器IP:3000`。未登录访问首页应跳转到登录页；健康检查：

```bash
curl -f http://127.0.0.1:3000/api/health
```

返回版本应为 `0.3.2`。

## 7. 离线升级

升级不会主动删除 `data/`，但仍需先备份：

```bash
bash scripts/backup.sh
```

离线部署包同时包含 `backup.sh`、`verify-backup.sh` 和 `restore.sh`。备份完成后先运行校验脚本，并把备份复制到不同磁盘或主机。

随后导入新版本 API/Web 镜像，把新部署包中的 Compose 文件复制到部署目录，将 `.env` 的 `CLOUDSITE_IMAGE_TAG` 改为新版本，再执行：

```bash
docker compose -f docker-compose.yml -f docker-compose.offline.yml up -d --wait
```

升级后检查 API 版本、目录和资源数量、合集、用户、最近同步记录及自动同步设置。

## 8. 回滚

保留旧版本镜像，不要使用 `latest`。发生问题时，把 `.env` 的 `CLOUDSITE_IMAGE_TAG` 改回旧固定版本：

```bash
docker compose -f docker-compose.yml -f docker-compose.offline.yml up -d --wait
```

如果新版本已经修改数据库且需要回滚数据，再恢复升级前经过校验的 SQLite 备份。

## 安全提示

- 不要执行 `docker compose down -v`。
- 不要把 `.env`、`data/` 或数据库上传到 GitHub Release。
- 离线附件只包含公开镜像和部署模板，不包含任何生产数据或密钥。
- 目标机器架构必须与附件一致。
